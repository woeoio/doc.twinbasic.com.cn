# docs/en/official 死链分析总结

## 📊 死链类型分析

### 1. **不带 `.md` 后缀的相对链接** ⭐ 最高优先级
**占比：约 60-70%**

```markdown
[FAQ](FAQ)                              → [FAQ](FAQ.md)
[Arrays](Tutorials/Arrays)              → [Arrays](Tutorials/Arrays.md)
[Features](Features)                    → [Features](Features/index.md)
[Attributes](Features/Attributes-Intro) → [Attributes](Features/Attributes-Intro.md)
```

**可否插件预处理：** ✅ **可以** - 这是最容易通过插件批量处理的类型

---

### 2. **Jekyll Attribute Lists** ✅ 已处理
**占比：约 10-15%**

```markdown
{: .no_toc }
{: #appobject }
{:style="width:45%; height:auto;"}
```

**可否插件预处理：** ✅ **已在 `jekyllPlugin` 中处理**

---

### 3. **HTML 后缀链接** ⭐ 中优先级
**占比：约 2-5%**

```markdown
[Defining interfaces](../../Features/Language/Interfaces-CoClasses.html#defining-interfaces)
```

**可否插件预处理：** ✅ **可以** - 转换为 `.md` 或移除 `.html`

---

### 4. **上级目录引用 `../`** ⭐ 低优先级
**占比：约 15-20%**

```markdown
[procedure](../Gloss#procedure)
[Defining coclasses](../../Features/Language/Interfaces-CoClasses#defining-coclasses)
```

**可否插件预处理：** ⚠️ **需谨慎** - 路径可能是正确的，只是目标文件不存在

---

### 5. **Jekyll TOC 语法** ✅ 已部分处理
```markdown
* TOC
{:toc}
```

**可否插件预处理：** ✅ **可以扩展插件移除**

---

### 6. **目录结尾链接 `/`** ⭐ 中优先级
```markdown
[Add Ins](tB/IDE/AddIns/)
[Menu](tB/IDE/Project/Menu/)
```

**可否插件预处理：** ✅ **可以** - VitePress 支持，但建议明确指向 `index.md`

---

### 7. **图片路径含空格**
```markdown
![image](Images/flags attribute.png)
```

**可否插件预处理：** ✅ **可以** - URL 编码或添加 `<` `>` 包裹

---

## ✅ 可通过插件预处理的类型汇总

| 类型 | 占比 | 实现难度 | 预估修复量 |
|------|------|----------|------------|
| 添加 `.md` 后缀 | ~60% | 简单 | 600+ |
| HTML → MD 转换 | ~3% | 简单 | 30+ |
| 目录 `/` → `/index.md` | ~10% | 中等 | 100+ |
| TOC 语法清理 | ~5% | 简单 | 50+ |
| 图片 URL 编码 | ~2% | 简单 | 20+ |

**总计：约 75-80% 的死链可以通过插件预处理解决**

## 🔧 建议的插件增强方案

当前 `jekyllPlugin` 可以扩展以下转换规则：

```typescript
// 1. 自动添加 .md 后缀（排除外部链接和锚点链接）
transformed = transformed.replace(
  /\[([^\]]+)\]\(([^)]+)\)/g,
  (match, text, url) => {
    // 排除外部链接、已有后缀、锚点链接
    if (url.startsWith('http') || url.endsWith('.md') || 
        url.endsWith('.html') || url.startsWith('#')) {
      return match;
    }
    // 目录链接处理
    if (url.endsWith('/')) {
      return `[${text}](${url}index.md)`;
    }
    // 添加 .md 后缀
    return `[${text}](${url}.md)`;
  }
);

// 2. HTML 后缀转 MD
transformed = transformed.replace(
  /(\[.*?\]\(.*)\.html(.*?)\)/g,
  '$1.md$2)'
);

// 3. 图片路径空格处理
transformed = transformed.replace(
  /!\[([^\]]*)\]\(([^)]+\s[^)]*)\)/g,
  (match, alt, url) => `![${alt}](${encodeURI(url)})`
);
```

## 🎯 结论

**`docs/en/official` 中约 75-80% 的死链类型可以通过扩展 `jekyllPlugin` 进行预处理修复。**

优先处理顺序：
1. 添加 `.md` 后缀（最大收益）
2. HTML 转 MD
3. 目录链接规范化
4. TOC 语法清理
